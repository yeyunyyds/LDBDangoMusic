# 0.4.2：按实机 DLL 校正 Source 接口

用户提供的 engine.dll / client.dll 仅在云端静态解析，未加载执行，也不随仓库或发布包分发。
SHA-256、PE 标识、接口构造器、对象、虚表和所用方法 RVA 记录在 vendor/source-binary-profile.json。

## 已发现的差异（索引从零开始）

| 项目 | 旧公开 SDK / 0.4.0 | 用户实际二进制 |
|---|---|---|
| Client 接口 | VClient015 | VClient016 |
| Shutdown | 2 | 3 |
| LevelShutdown | 5 | 6 |
| View_Render | 23 | 25 |
| Engine 接口 | VEngineClient013 | VEngineClient013 |
| WorldToScreenMatrix | 36 | 37 |
| WorldToViewMatrix | 37 | 38 |

实际引擎的槽 36 返回全局字符串缓冲区地址，不能当作矩阵读取。
因此仅修改接口名称会导致错误调用，必须同时校正布局。
GetScreenSize / IsInGame / IsDrawingLoadingImage 仍分别为 5 / 26 / 28。

## 静态证据

- client 的接口注册初始化函数将 VClient016 和构造器 RVA 0xa87d0 配对；构造器返回 RVA 0x6c4a98 的对象，虚表 RVA 0x56441c。
- View_Render[25] = RVA 0xa8bf0，函数引用 CHLClient::View_Render，并接收 rect，检查 width/height，再调用视图渲染；ret 4。
- Shutdown[3] / LevelShutdown[6] 的函数分别有整体关闭和 level_shutdown 路径；修正后的 RVA 为 0xb2360 / 0xb14e0。
- engine 的 VEngineClient013 构造器 RVA 0x5cb80 返回 RVA 0x425504 的对象，虚表 RVA 0x359dec。
- 引擎矩阵 getter[37]/[38] 分别通过渲染器虚表的槽 13/12 返回矩阵引用；对应 RVA 0x5d620 / 0x5d630。
- 渲染器两项 getter 返回视图栈中的矩阵或主视图缓存，未复制字符串缓冲区或任意猜测 shader 常量。

scripts/verify_source_binaries.py 用 Python 标准库离线核对文件哈希、PE 标识、构造器返回对象、对象虚表及方法地址：

```
python scripts/verify_source_binaries.py --client client.dll --engine engine.dll
```

## 运行边界

新适配只接受已核对的 PE 时间戳/SizeOfImage 和所有用到的虚表入口 RVA；ASLR 下使用相对地址。
运行时检查不是全文件 SHA 验证，也不构成文件完整性认证。离线工具另外校验上传文件的完整 SHA。
其他构建、改过相关虚表的插件或未知布局会被拒绝，并保留屏幕歌词。
本版没有给未知游戏构建强行套索引，也没有分发游戏 DLL。

## 安装与验收

退出游戏，替换 bin/neko/plugins/L4D2DangoMusic.dll，保留原配置，确认 worldLyrics=true。
0.4.2 会分别报告实际接口查询结果、布局不匹配和回调内的场景/矩阵状态。
进图后预期日志：Source camera installed: verified VClient016 View_Render[25]...
若仍回退，查看 Source capture 状态；必要时开启 cameraDiagnostics=true 收集新增 source_camera 状态和矩阵。

已完成：对用户 DLL 的静态核对、Linux 回归、x86 交叉编译及导出/包校验。
