# 0.4.3：构建校验与现有回调链

用户新日志确认 0.4.2 已找到 VClient016 / VEngineClient013，但在以下任一校验中被拒绝：
client PE、engine PE、client 方法 RVA、engine 方法 RVA。旧日志把四项合并且短路执行，无法区分。
因此不能仅凭现有日志断言是游戏更新或 L4N 钩子造成。

## 改进

- 分别记录两个模块的 Machine、TimeDateStamp、SizeOfImage、预期值和匹配结果。
- 两个构建标识必须都匹配已上传 DLL 的资料，否则不尝试调用或挂接方法。
- 对不同于原始 RVA 的虚表项，记录槽号、当前地址和目标所属模块名（或 private-or-unmapped）。
- 支持游戏内已有虚表回调：在已验证构建和已确认槽位前提下，当前入口与原始游戏入口均必须位于可执行已提交内存中。
- 原函数绑定为接口中的当前入口，自己的回调完成后继续调用它，不绕过、不替换已有 L4N 功能。
- 退出恢复时只还原仍指向自身的槽位。
- 不能识别或不可执行的入口仍拒绝安装；没有猜测新的接口槽位，也没有移除游戏构建检查。

“可执行”只证明入口可以调用，不证明第三方钩子的实现正确。兼容性仍要实机验证。
如果此后日志显示构建标识不同，本版仍会拒绝相机功能，需要根据实际值继续排查。

## 使用

退出游戏替换 bin/neko/plugins/L4D2DangoMusic.dll，保留原配置，完整重启并进图。
请检查本次版本 0.4.3 的日志区段，旧的 0.4.0/0.4.2 内容可能仍在文件前面。
如果仍未显示世界锚点，提供新的 L4D2DangoMusic.log：Build check 和 Method check 会指出具体差异。

已验证：x86 交叉编译、原有 Linux 回归、导出/文件校验。
Windows 回调链测试已编译，未在 Windows 执行。真实 L4N 回调链与相机效果未验收。
