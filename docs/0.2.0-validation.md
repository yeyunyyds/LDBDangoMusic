# 0.2.0: SwapChain 绘制修正

## 接口证据

读取 LDB 分支 `codex/steam-reshade-plugin-entry-test`，提交
`db5cb944314bb50c2e61835d5f0e8855c089e2e6`。

该 SDK 相比 90083c0 在 PresentInfo 中间增加 swap_chain，并在插件回调表中增加
on_swapchain_created / on_swapchain_destroyed。虽然 ABI 数字仍为 1，结构布局已经改变。
Host Manager 会拒绝 struct_size 不匹配的旧 DLL。此插件也严格检查大小，不能混用旧 Host。

0.1.0 明确跳过 is_swapchain_present；这是一条不绘制的代码路径，不能仅靠启用插件解决。
此外，0.1.0 示例 demo=false，只启用插件不会启动演示。它们是已确认的代码问题，
尚无用户 Host 日志证明实际机器具体遇到了哪一项。

## 修复

- 替换为新官方 SDK，补齐新回调表及结构大小校验。
- 优先从当前 swap_chain 取得 backbuffer，覆盖主/附加 SwapChain。
- Device Present 未提供 chain 时才退回 Device 主 backbuffer；SwapChain Present 缺链时明确报错。
- 保存/恢复目标、深度表面、额外 MRT、viewport 和完整 D3D9 state block。
- 字体纹理创建失败不再永久缓存失败结果，后续帧可重试。
- demo 默认 true，安装包内实际配置也是 true；左上角显示固定 DEMO 标识。
- 记录配置绝对路径和模式、首个 Present 路径、首个绘制提交，以及分阶段 HRESULT 错误。

## 已运行

Linux 核心和模拟 HTTP 集成检查通过，新增主/附加链选择、Device fallback、缺链拒绝回归。
MinGW x64 严格编译 DLL 和更新的 Windows 验证程序；检查 DLL 导出与系统依赖。

目标/viewport/blend 恢复，以及 Reset 后再次绘制。之后进行 LDB + DXVK/ReShade 实机检查。

## 用户验收

1. 完全退出游戏和 Host，使用上述 LDB 提交或确认兼容的新版。
2. 把 ZIP 内 bin 文件夹合并至游戏根目录；它只包含插件及 demo 配置，没有覆盖 LDB 本体。
   若保留旧配置，务必把实际 config.json 的 demo 改成 true。
3. server.plugins = True，启动游戏，应出现左上 DEMO 标识和循环歌词。
4. 如仍空白，在 Host 日志搜索 LDBDangoMusic / LDB_HOST_PLUGIN：
   - query-rejected：检查 Host 是否匹配新 SDK、是否仍安装旧 DLL。
   - initialization-rejected：检查配置语法及相邻错误。
   - config=... mode=DEMO：确认实际读取的配置。
   - first Present path=SwapChain current-chain=yes：确认走入新的绘制路径。
   - render-error operation=... hr=...：保留具体错误，不只报告“插件已启用”。
   - first textured draw submitted：仅说明 API 接受绘制，仍需确认游戏画面。
5. 实测窗口化/全屏切换、Reset、暂停/恢复；切到播放器模式时 demo=false，再完整重启。
