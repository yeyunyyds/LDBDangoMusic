# 实验：固定在墙面的挂画歌词

分支：`experiment/wall-mounted-lyrics`。

## 目标与结论

可行方向是：将歌词放置在地图墙面的固定三维平面上，相机走近或转头时，平面保持自己的位置与朝向，产生真实的透视缩短和视差。相机需要走到合适角度阅读它；歌词不自动朝向相机，不会在靠近时自行后退或定时回屏。

实现这一效果不需要先提取完整地图。首选是 Source 的碰撞射线，取得墙面命中点与法线；完整几何提取属于另一项更大的工作，可作为后续支持自动布置的补充。

本分支已推进到手动放置实验包：接入有构建校验的射线调用、固定文字平面绘制和保守遮挡采样。使用方式与当前未实机验证的边界见 [实验指南](../wall-experiment-guide.md)。以下记录原始调查与后续自动布局路线。

## 为什么现有世界歌词还不是挂画

现有路径将歌词中心投影到屏幕，再按屏幕坐标绘制文字四边形。中心是世界锚点，但字面仍面向屏幕。
挂画需要固定平面的中心、法线、右向量和上向量，把文字每个角点都放入这个平面后再投影，保留逐顶点深度和 `rhw`。四个角的透视不同，因此斜看时文字自然变窄，而不是继续正对相机。
墙面模式必须绕过现有的最近距离保护和定时回屏，不能把这些功能继续作用到挂画位置。

## 已取得的证据

对之前提供的游戏 `engine.dll` 进行静态读取，未加载或执行该 DLL：

| 项目 | 结果 |
| --- | --- |
| SHA-256 | `8a6d468059394bf4cfce32f11dcba12ef45de88da1373084d5a2916d0bf7ba86` |
| 客户端射线接口注册名 | `EngineTraceClient003` |
| 注册记录 RVA | `0x340e60` |
| 工厂函数 RVA | `0x1774e0` |
| 返回对象 RVA | `0x42fa5c` |
| 虚表 RVA | `0x387474` |
| 公开 SDK 中 TraceRay 候选槽 | `5`，对应本 DLL 该槽函数 RVA `0x179760` |

接口注册、工厂返回对象和虚表条目已静态定位；函数签名、参数布局已有静态指令证据及编译期契约；实际引擎派发尚未完成运行验证。不能仅因接口名相同就调用公开 SDK 中的槽位，已有相机适配也表明游戏构建可能与公开 SDK 存在差异。

完整定位结果见 [engine-trace-discovery.json](engine-trace-discovery.json)，包含 `runtime_dispatch_verified=false`。
复核工具：

```bash
python scripts/discover_engine_trace.py /path/to/engine.dll
```

公开资料参考 [HL2SDK l4d2 的 IEngineTrace](https://github.com/alliedmodders/hl2sdk/blob/l4d2/public/engine/IEngineTrace.h)、`public/cmodel.h`、`public/gametrace.h` 和 `public/trace.h`。
SDK 的 Ray_t 使用对齐向量，trace_t 包含平面、表面和实体字段；这些布局与过滤器的 MSVC x86 ABI 都需核对。调用目前被独立实验开关隔离，只有当前已静态核对的构建能够绑定；Windows模拟ABI测试和实际游戏验证分开进行。

## 获取场景信息的三条路线

| 路线 | 可以取得什么 | 用途与边界 |
| --- | --- | --- |
| Source 碰撞射线 | 某一方向的命中点、法线、距离及表面信息 | 推荐起点，足够寻找附近墙面；不是完整场景，也不等于可渲染网格。 |
| 读取地图 BSP | 静态面的顶点、边、平面和部分场景数据 | 可建立墙面多边形与空间索引；还要处理版本、压缩 lump、HDR 面、位移地形和资源路径。 |
| 捕获运行时渲染几何 | 渲染调用中的网格和材质相关状态 | 需要还原顶点格式、实例变换和绘制阶段；D3D9 Device 不会直接返回完整语义场景。 |

“完整场景”包含静态 BSP、位移地形、静态道具和动态实体。单独读 BSP 并不能得到与当前游戏画面完全一致的运行时场景。这里不建议先做完整场景导出，也不需要引入 LDB。

## 推荐实施顺序

### 1. 只验证射线，不绘制歌词

核对当前构建的 TraceRay 调用约定、Ray_t/trace_t 尺寸和字段偏移，以及过滤器虚表。
在确定的引擎调用线程执行诊断射线，输出命中点、法线、fraction、startsolid/allsolid 和表面标识；不在音乐网络线程或未经确认的 Present 线程调用引擎碰撞接口。
可以沿用现有 Source 回调来传递请求与发布结果，但仍需验证该回调中调用碰撞接口的有效性。

首轮只接受静态世界墙面，跳过地面、天花板、未命中及起点在实体内的结果。公开 SDK 的 `TRACE_WORLD_ONLY` 明确不测试静态道具，因此“世界墙面”与“所有可见物体表面”应分开验收。

### 2. 准星手动放置一幅挂画

增加实验命令：准星指向墙面并放置固定示例歌词。命中点作为中心，法线决定朝向，使用世界向上的方向构造平面基。
文字略离墙面，避免重合闪烁。记录地图 epoch；切图时清除。相机移动和旋转不改变平面基，也不触发回屏或靠近后退。

先以整行纹理平面验证透视和方向；再将逐字四边形放入同一平面，接回逐字动画。普通 HUD 字符绘制函数不能直接复用为贴墙四边形。

### 3. 墙面范围与遮挡

只有中心命中不足以证明整块文字能放下。检查角点及内部网格采样，排除跨拐角、门洞或法线变化过大的位置。多点采样只能降低错误概率，严格连续面验证还需 BSP 面多边形等几何信息。

初期可通过视线射线判断是否隐藏整幅挂画，避免明显穿墙；这不是精确的逐像素遮挡，门框等局部遮挡仍会有取舍。
真正的部分遮挡应接入与场景一致的深度测试或可靠的深度资源。现有 Present 绘制会解除深度表面，不能宣称仅提供世界坐标就已经有墙体遮挡。

### 4. 沿弯曲通道自动布置

在玩家附近按低频射线扇形搜索左右候选面，选择可容纳文字的局部平面，按新歌词依次放置。已经放好的挂画不随之后的射线结果重新旋转。
对相邻挂画设置最小间距、最大数量和寿命；遇到门洞或拐角，跳过或寻找另一处候选面。曲面墙采用小尺寸局部平面；沿曲面弯曲文字属于进一步的几何变形功能。
动态门和移动物体先不支持；如要贴附它们，需要实体局部坐标、实体变换与失效处理。

## 几何原型与验收

[src/wall_panel.hpp](../../src/wall_panel.hpp) 提供：

- 根据命中点与法线构造 Z-up 固定平面。
- 平面上的 UV 坐标转换为固定世界角点。
- 输出各顶点屏幕坐标、深度、`rhw` 和 UV，供后续 D3D9 透视四边形绘制使用。
- 背面、地图 epoch 不符及非法输入拒绝。

该原型只做投影。跨近裁剪面的面板目前整体跳过，没有实现多边形裁剪、墙面范围、可见性、文字纹理或 GPU 绘制。

`tests/wall_panel_test.cpp` 验证相机平移与转头时平面不变、斜视的角点 rhw 不同、透视缩短、通道转弯后的另一朝向墙面，以及背面/切图失效等条件。

```bash
bash scripts/test.sh
```

实机第一阶段的验收应是：正对墙面、侧身观看、前后走动、背向墙面、隔墙与切图。通过后再接入音乐歌词，最后处理自动沿墙布局。
