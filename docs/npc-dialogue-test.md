# NPC / 生还者台词跟随实验 · build 1

分支 `experiment/npc-dialogue`，基于 `experiment/entity-attachments` 的归档提交 `81acce6` 独立开发。原实体实验、main、zip、正式 Release、挂画布局测试分支不因此变化。本轮提供可编译的接收、解析、匹配与绘制链路，真实 L4D2 画面尚未验收。

## 已接入的路径

```text
VClient016::DispatchUserMessage[35]
  → 读取 CloseCaption / CloseCaptionDirect 的只读副本
  → 32 位字幕哈希、15 位持续时间、1 位标志
  → 后台读取原生 VCCD 字幕字典（支持 VPK）
  → 去除显示标记，解析“Zoey: 文本”等说话者前缀
  → 用 m_survivorCharacter 匹配唯一存活生还者实体
  → 完整句柄 + 地图 epoch + 有效网络姿态
  → 角色附近的台词气泡
```

没有调用未知实体虚函数，也没有消耗原生消息读指针。原始消息无论解析是否成功都会按原参数调用原函数，返回值保持原样。只在用户开启实验后安装一个经当前 DLL 静态证据校验的虚表槽钩子；不同构建、不同目标指针或代码不符时拒绝安装。关闭后停止采集/显示，卸载时仅在槽位仍属于本插件时恢复。

字幕资源 IO、文本解析和 JSONL 使用专门后台线程，不依赖音乐 API 的响应。引擎回调只做有界读取与有界队列入队；实体数据仍由既有游戏线程采集器发布。跨线程只读取不可变快照。

## 测试方法

1. 完整退出游戏。备份现用 DLL 到插件加载目录之外，仅替换实验 DLL，保留 config.json。
2. 开启游戏原生对话字幕，进入有生还者对白的地图，确认屏幕上确实出现原生字幕。
3. 打开“更多设置 → 实验：角色台词跟随”。关闭旧的手动“实体跟随测试”可减少画面混淆；本实验不依赖那个锁定目标。
4. 开启采集，等待 `Caption message hook ready` 和字典数量大于 0。默认关闭，菜单设置仅本次会话有效。
5. 选“测试角色”，选择一个在视野里的实际队友角色。只对唯一匹配的存活实体显示四秒示例；这一步不需要字幕字典或音乐 API，用于分离实体/绘制问题。测试行在诊断里为 `type=test, synthetic=true`。
6. 触发真实对白，观察接收、解析、匹配计数，以及角色走动时的文字。可以同时显示多个不同角色，每个实体的新台词替换其旧台词。
7. 点“导出状态与实体快照”，等待数秒，再关闭采集。提供下列三个文件，不需要再发游戏 DLL。

```text
bin/neko/plugins/L4D2DangoMusic/
  L4D2DangoMusic.log
  dialogue.jsonl
  entities.jsonl
  caption-resources/  # 可选，原生字典覆盖
```

JSONL 追加保留历史；字幕记录带 `dialogue_build: 1`，实体诊断帧带 `diagnostic_build: 7`，新增 survivor_character / health / life_state。dialogue.jsonl 达 32 MiB 后本次进程停止写诊断，气泡仍继续；下一次测试前退出游戏并改名旧文件。

## 字典来源

按所选语言先读取，再按哈希回退英文。每种语言的优先顺序为：

1. 插件数据目录 caption-resources 内的 subtitles_<language>.dat、closecaption_<language>.dat。
2. 游戏 left4dead2_dlc3、dlc2、dlc1、left4dead2 内的 resource 散装文件和 pak01_dir.vpk 条目。

使用 VCCD v1 的哈希目录定位 UTF-16 文本；支持 VPK v1/v2、预载字节、目录内嵌数据和外部分包。只读目标字幕条目，不解压整包。路径来源、字典条目数和解析错误会写入 resources 记录。分发包不包含任何游戏资源。

自定义 addon 或其他语言的实际字幕字典可能不在自动搜索范围。可把提取的字幕 .dat 放到覆盖目录，使用对应 schinese / english 文件名，再点重新载入。不会把屏幕 OCR 或语音识别当成原生字幕。

## 匹配与显示规则

- 英文八角色名以及常见简体/繁体中文别名，支持半角/全角冒号、颜色/字体标签和 [Name]: 前缀；未知前缀明确记为 unknown_speaker。
- 原始网络角色编号按 DLL 中核对的 0 Nick / 1 Rochelle / 2 Coach / 3 Ellis / 4 Bill / 5 Zoey / 6 Francis / 7 Louis 解释。旧战役辅助函数另有编号转换逻辑，本实验不直接调用；实际网络值会完整记录，需实机验证，不猜测转换。
- 仅匹配 CTerrorPlayer / SurvivorBot、team=2、角色编号一致、非休眠、有效姿态，已知死亡状态会排除。玩家昵称不参与匹配。同角色多个候选拒绝猜测。
- 完整句柄与地图 epoch 防止实体索引复用、切图后串人；显示时再次检查实体身份和生存状态。快照过期、删除、休眠、地图变化时隐藏。
- 最多八个角色同时有台词；每个实体保留最新一句，相同文本的短时间重复消息合并。使用消息持续时间，零值按三秒，展示范围限制为 0.5–30 秒，末尾 250ms 淡出。
- 网络实体列表约每 200ms 更新，属于网络姿态实验，不是插值后的头骨姿态。高度可在 72 / 84 / 96 / 112 游戏单位切换。没有墙体遮挡。自己第一人称角色的头顶一般不在相机视野内。
- 与 LX 播放状态及歌词总开关独立；用本页开关关闭台词气泡。气泡颜色/字体沿用歌词样式，位置预览期间暂不叠加气泡。

## 如何看诊断

| 状态 | 说明 |
| --- | --- |
| 接收为 0 | 尚未走到字幕消息入口；确认原生字幕可见及钩子状态，可能需要研究客户端本地字幕路径 |
| 字典为 0 | 字典文件未找到或格式/分包读取失败，查看 resources 的 sources/errors |
| hash_not_found | 接到了编号，但当前字典没有对应文本，需核对语言、DLC 或 addon 覆盖 |
| unknown_speaker | 找到文字，但没有识别到独立说话者前缀；该行保留原始文本供判断 |
| no_entity | 没找到该角色的有效实体，查看 players 列表中的角色编号、队伍和存活状态 |
| ambiguous_role | 同名角色有多个有效实体，未自动挂载 |
| stale_inventory / wrong_map | 快照过期或地图不符，未复用旧目标 |
| matched | 成功产生台词；仍需角色在视野内、距离不超过 1200 游戏单位才能绘制 |
| expired_or_duplicate | 台词处理时已过期，或与同实体的短时间重复消息合并 |

`type=test` 只证明示例链路；真实自动接收必须看到 CloseCaption 或 CloseCaptionDirect 记录。如果姓名由游戏 HUD 单独拼接、实际字典不包含姓名，此版本会保留诊断并拒绝按时间猜人，下一轮再补另一种说话者关联入口。

实际 DLL 的只读静态证据保存于 [dialogue-abi.json](research/dialogue-abi.json)，可运行 scripts/verify_dialogue_profile.py 复核。云端不加载或执行上传的游戏 DLL。
