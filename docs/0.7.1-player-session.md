# 0.7.1 暂停、播放器重开与重复副本

## 双份歌词

用户已确认新旧插件同时加载。它们分别拥有自己的菜单、状态和绘制，旧菜单的开关/颜色只能控制旧副本。
本版安装脚本扫描 Client 和 Host 的标准插件目录，以本项目名称和插件导出标记识别旧二进制，包括改名副本和 .dll.bak/.disabled 备份；移到 `bin/neko/plugins-disabled/L4D2DangoMusic-时间戳/`，不再放在插件搜索目录里。
当前 DLL 的备份也放在那里；配置保留。脚本不卸载已经加载的模块，升级前必须退出游戏和 Host，升级后重新启动。

新版菜单标题明确包含 **L4D2DangoMusic 0.7.1**。进入“版本、路径与播放器诊断”，可看到当前 DLL 完整路径、游戏 PID、其他已加载相关模块及播放状态；日志也记录这些信息。
模块枚举仅覆盖当前游戏进程，不能证明 Host 里没有额外的旧插件；Host 的标准目录由安装脚本检查。

0.7.1起的副本通过进程内命名互斥对象只允许一个实例取得绘制权，后加载副本显示“重复副本已阻止”，不安装 D3D 钩子。不尝试卸载运行中的其他 DLL，避免破坏钩子调用链。旧版本没有此机制，仍应通过安装脚本移出旧文件。

## 播放状态清理

已发现0.7.0的两个独立问题：暂停时保留当前实例并继续3秒回屏；API错误后保留歌词缓存，重开同一首歌可能沿用旧缓存。

- 暂停/停止：清除当前句、退场句和世界锚点，不再让旧句继续回屏。正常歌词/歌曲信息暂时隐藏。
- 恢复播放：新的播放代次，重新获取歌词和核对当前进度；同一首歌、同一句编号也不会复用旧实例。
- API连接失败：首次请求失败即发布断开状态、清除歌曲键和歌词缓存，不再等待旧快照额外存活3秒。
- 重连、换歌、真正的进度跳转：使歌词缓存及实例代次失效，再获取对应歌词。
- 歌词响应返回后，再读一次播放状态；若中途暂停、换歌或进度明显跳转，丢弃旧响应。
- 歌词接口暂时失败时不把空缓存当成永久结果；状态轮询继续，约1秒后重试。状态接口在验证时失联会使整个连接失效。
- 每个快照带播放代次，即使渲染线程错过中间暂停快照，也能清掉旧实例。
- 快照过期或进度达到歌曲结尾：停止正常歌词显示和回屏。正在进行的网络调用仍受原有超时约束。

位置调节页的固定预览仍由菜单控制，和播放器是否暂停/连接无关；点“保存设置并结束预览”恢复正常歌词显示。
歌曲播放中的1秒旧句停留、1～9个轮换位置、3秒长句回屏和0.6.1底图恢复保留。

## 验证与诊断

新增生产状态机回归覆盖暂停后长期不复活、同歌恢复/播放器重开重新取词、渲染漏过暂停快照、真实拖动与微小采样抖动、歌曲结束、快照过期恢复、歌词请求失败重试、中途换歌及状态验证失联。
既有API/动画/相机/位置/生命周期测试继续执行。Windows x86模拟宿主增加改名DLL重复加载检查；已交叉编译，云端未执行 Windows/D3D9、PowerShell安装或实际游戏验收。

日志新增 `Player state connected=... playing=... generation=... position_ms=... timeline_lines=...`，首次断开记录错误原因。相机诊断JSONL增加 `player` 状态和 `position_preview`。
若清理副本后仍异常，请提供本次启动生成的 L4D2DangoMusic.log；无需再次发送 engine.dll/client.dll。
